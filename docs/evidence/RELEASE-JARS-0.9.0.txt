Why they differ. Git stores every file under src/ with LF endings (.gitattributes eol=lf). In the main
checkouts, seven files on master and one on mc-26.2 had CRLF on disk, which git status does not report.
Java sources compile to the same classes either way; resources are packed as they sit on disk, so the one
resource among them, pathweaver.mixins.json, went into the jar with CR bytes. On mc-26.2 the CRLF file was
a Java source, so its main jar was unaffected and only its sources jar differed (a6dd3028... before).

The comparison, 0ba3d71a against 47e24d24:
  same entry names, same order        True
  entries whose bytes differ          pathweaver.mixins.json
  equal after removing CR             True
  parsed JSON equal                   True

What stands on it: the measured jar and the shipped jar give Mixin the same configuration, so the
measurements describe the shipped jar. The shipped 26.1.2 jar was also booted itself on a clean server
without Cloth Config (no-cloth-2026-09 row 6, on the master branch). The tag message before this correction named 0ba3d71a
and the pre-normalisation sources jars.

The release script builds only from pinned clean worktrees, so it cannot pick up a checkout's disk state.
