That jar is NOT byte-identical to the 53c591f one, and the commit message for 0843903 claimed "no
production bytecode changed", which is wrong as written. Measured: of 118 class entries, 4 differ,
all of them files whose only edit was comments (LithiumPathfindingCompatibility and its Bundle,
PathNavigationMixin, WallClimberNavigationMixin). Adding comment lines moves the LineNumberTable.

What is true, and is what the harness series rests on: the instruction streams are identical. javap -p -c
output for all four classes is byte-for-byte equal between the two jars, and the other 114 class
entries and every non-class entry hash the same. So the nine-harness series taken at 53c591f describes
the same executable behaviour as 0843903, and it was not re-run for a comment and unit-test commit.
